# القرآن الكريم — دليل النشر والصيانة

قراءة وتصفح القرآن الكريم برواية حفص.

تطبيق ويب لقراءة القرآن والاستماع إليه، يعمل كتطبيق مثبّت (PWA) وبدون إنترنت.
هذا الملف للمطوّر: ماذا يُرفع، ومتى يُرفع رقم الكاش، وكيف تعمل الكاشات.

## روابط

- التطبيق: [القرآن الكريم](https://magziko.github.io/equran/)
- المستودع: [magziko/equran](https://github.com/magziko/equran)
- تطبيق الراديو (نفس الأصل `magziko.github.io`): [الراديو](https://magziko.github.io/Radio)

## الملفات

| الملف | وظيفته |
|---|---|
| `index.html` | التطبيق كله (الواجهة والمنطق، بدون بيانات القرآن). |
| `quran-data.js` | بيانات القرآن (114 سورة / 6236 آية)، تُحمَّل بشكل غير معطِّل للصفحة. |
| `sw.js` | الـ Service Worker: العمل بدون إنترنت، وكاش التفسير والتلاوة والصور. |
| `manifest.json` + الأيقونات | التثبيت كتطبيق (`icon-192.png`, `icon-512.png`, والنسخ `maskable`). |

## قائمة النشر

1. ارفع **الملفات المعدّلة معًا** إلى المستودع (`index.html`, `quran-data.js`, `sw.js`).
   - `sw.js` يعتبر `index.html` و`quran-data.js` ملفات أساسية: لو أحدهما غير موجود على الموقع، يفشل تثبيت الـ SW الجديد ويبقى القديم شغالًا (هذا مقصود حتى لا يتعطل التطبيق).
2. انتظر انتهاء نشر GitHub Pages، ثم افتح الموقع مرتين (الأولى تحمّل النسخة الجديدة في الخلفية، والثانية تعمل بها).
3. المستخدمون الذين فتحوا التطبيق من قبل تظهر لهم رسالة **"يوجد تحديث"** عند تغيّر `index.html`.

## متى أرفع رقم الكاش في `sw.js`؟

الثابت `CACHE_NAME` (حاليًا `quran-app-cache-v8`).

- **ارفعه** (`v8` → `v9`) عند: تعديل `quran-data.js`، أو تغيير قائمة `CORE_SHELL`/`OPTIONAL_SHELL`، أو إضافة ملف أساسي جديد، أو أي تغيير في منطق `sw.js` تريد أن يصل للجميع فورًا.
  - تعديل `quran-data.js` وحده **لا** يُظهر رسالة "يوجد تحديث"، لأن المقارنة تتم على `index.html` فقط. رفع الرقم هو ما يجبر الأجهزة على تحديث البيانات.
- **لا حاجة لرفعه** عند تعديل `index.html` فقط: الصفحة تُحدَّث في الخلفية وتظهر رسالة التحديث.

## الكاشات

كل التطبيقات على `magziko.github.io` (القرآن، الراديو، …) تشترك في نفس الأصل وبالتالي في نفس `CacheStorage`. لذلك:

| الكاش | المحتوى | يُحذف عند رفع الرقم؟ |
|---|---|---|
| `quran-app-cache-vN` | ملفات التطبيق (`index.html`, `quran-data.js`, الأيقونات…) | نعم (القديم فقط) |
| `quran-tafsir-offline-v1` | التفسير والترجمات المحمّلة | لا |
| `quran-share-photos-v1` | خلفيات صور مشاركة الآية | لا |
| `quran-audio-offline-v1` | التلاوة المحمّلة (ملفات mp3) | لا |

- عند التفعيل يحذف الـ SW الكاشات التي تبدأ بـ `quran-app-` **فقط**. لا تغيّر هذه البادئة ولا تحذف كاشات أي تطبيق آخر.
- أسماء كاشات التفسير والتلاوة والصور لا تبدأ بـ `quran-app-` عمدًا حتى لا يفقد المستخدم ما حمّله مع كل تحديث.

## العمل بدون إنترنت

- **التطبيق والنص:** يُخزَّن تلقائيًا بعد أول زيارة.
- **التفسير والترجمة:** من الإعدادات ← تاب "التفسير والترجمة" ← تحميل. المصادر من `cdn.jsdelivr.net` (`spa5k/tafsir_api`, `fawazahmed0/quran-api`). سجل ما تم تحميله محفوظ في `localStorage` (المفتاح `tafsirOfflineDone`).
- **التلاوة:** من الإعدادات ← تاب "الصوت والتلاوة" ← "تحميل التلاوة للاستماع بدون إنترنت". التحميل لسورة واحدة وللقارئ المختار فقط.
  - الملفات من `everyayah.com/data/…` (قراء آية-بآية) وخوادم `mp3quran.net` (ملف لكل سورة).
  - الـ SW يخدم الملف المحمّل مع دعم التقديم والتأخير (طلبات `Range`)، ولا يتدخل في الملفات غير المحمّلة.
  - **شرط:** هذه الخوادم يجب أن ترسل ترويسة `Access-Control-Allow-Origin` حتى تستطيع الصفحة حفظ الملفات. للتحقق:
    ```
    curl -sI -H "Origin: https://magziko.github.io" https://everyayah.com/data/Husary_128kbps/001001.mp3 | grep -i access-control
    ```
    كرّر الأمر مع رابط من كل نوع خادم mp3quran تستخدمه. لو لم تظهر الترويسة فلن يعمل التحميل لهذا القارئ (تظهر للمستخدم رسالة خطأ واضحة).

## إضافة إعداد جديد

زر "استعادة الإعدادات الافتراضية" يحذف مفاتيح `localStorage` المذكورة في المصفوفة
`SETTINGS_KEYS_TO_RESET` داخل `index.html` (ويترك المفضلة والملاحظات وخطط الختم ومواضع القراءة).

> عند إضافة إعداد جديد يُحفظ في `localStorage`: أضف مفتاحه لهذه المصفوفة، وإلا لن يُعاد ضبطه.

## التشغيل المحلي واختبار الأوفلاين

```
python3 -m http.server 8000
```

ثم افتح `http://localhost:8000` (الـ Service Worker يعمل على `localhost` و`https` فقط).

لاختبار العمل بدون إنترنت: افتح الموقع مرتين، ثم من أدوات المطوّر ← Application ← Service Workers
فعّل **Offline** (أو Network ← Offline) وأعد تحميل الصفحة.

## استكشاف الأخطاء

| العَرَض | السبب المحتمل | الحل |
|---|---|---|
| "تعذر تحميل بيانات القرآن الكريم" عند فتح الصفحة | `quran-data.js` لم يُرفع أو تعذّر تحميله | ارفع الملف وتأكد أنه بجانب `index.html`. |
| لا تظهر التحديثات عند المستخدمين | الـ SW القديم ما زال يخدم النسخة المخزّنة | ارفع رقم `CACHE_NAME` وأعد النشر. |
| تثبيت الـ SW الجديد لا يكتمل | ملف من `CORE_SHELL` غير موجود على الموقع | ارفع كل الملفات الأساسية معًا. |
| "تعذر تحميل التلاوة" عند التحميل للأوفلاين | الخادم لا يرسل ترويسة CORS، أو انقطع الاتصال | اختبر الخادم بأمر `curl` أعلاه. |
| المساحة المتاحة قليلة على الجهاز | المتصفح قد يحذف التخزين تلقائيًا | التطبيق يطلب حماية التخزين (`persist`) لكن المتصفح قد يرفض، خصوصًا على iOS. |
